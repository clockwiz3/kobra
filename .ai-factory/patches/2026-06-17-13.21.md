# Модалка без фона/цветов: Teleport в `<body>` вынес её из тематического поддерева

**Date:** 2026-06-17 13:21
**Files:** resources/js/components/ui/BaseModal.vue, resources/js/components/ui/__tests__/BaseModal.test.ts
**Severity:** high

## Problem

Диалог подтверждения (`ConfirmDialog` поверх `BaseModal`) рендерился «голым»: без панели-карточки (`.modal` без фона), без заливки кнопок, оверлей-скрим не работал — текст висел прямо на странице. Характерная примета: заголовок отрисован шрифтом **Fraunces** (serif), хотя активная тема — `pixel` (должен быть Pixelify Sans). Скругления и сам факт открытия/закрытия работали.

## Root Cause

`BaseModal` использовал `<Teleport to="body">`. Тематические CSS-переменные (`--surface`, `--bg`, `--surface-2`, `--text`, `--border`, `--accent`, `--grad`, `--shadow`, …) объявлены под селектором `[data-theme="…"]`, который `useTheme()` вешает на элемент `#app.ds-root`. При телепортации в `<body>` модалка оказывается **вне** `.ds-root`, поэтому все `[data-theme]`-scoped переменные для неё **undefined**.

Следствия:
- `background: var(--surface)` → невалидно → нет фона панели;
- оверлей `color-mix(in srgb, var(--bg) …)` → невалидно → скрим прозрачный;
- `.btn-primary { background: var(--grad) }` → нет градиента;
- `color: var(--text)` (задаётся на `[data-theme]`) → наследуется чёрный с body.

Уцелели только переменные уровня `:root` (радиусы, `--font-head/body`, `--ease`) — отсюда правильные скругления и serif-шрифт-fallback (`:root --font-head: 'Fraunces'`), что и было главной уликой.

## Solution

Телепортируем в `.ds-root`, а не в `<body>`:
- Добавлен проп `to?: string` со значением по умолчанию `'.ds-root'`; шаблон — `<Teleport :to="to">`.
- `.ds-root` — прямой потомок `<body>`, поэтому `position: fixed` оверлей по-прежнему не клипается overflow/stacking-контекстами вложенных контейнеров (канбан-колонки), но модалка остаётся внутри тематического поддерева → все CSS-переменные резолвятся во всех трёх темах.

Добавлен регресс-тест: монтируем `BaseModal` БЕЗ стаба teleport, при наличии `<div class="ds-root">` в DOM, и проверяем, что `.overlay` оказался внутри `.ds-root`, а не прямым ребёнком `<body>`.

## Prevention

- **Любой Teleport в дизайн-системе на CSS-переменных должен целиться в тематический корень (`.ds-root`), а не в `<body>`/`document.body`.** Тема — на `.ds-root`, значит всё, что использует токены, обязано жить внутри него.
- При ревью оверлейных компонентов (modal/drawer/toast/popover) проверять цель Teleport.
- Тесты с `stubs: { teleport: true }` НЕ ловят этот класс багов (контент рендерится inline) — нужен хотя бы один тест с реальным teleport, проверяющий цель.
- Альтернатива на будущее: дать тематическим токенам fallback (`var(--surface, #fff)`) как defense-in-depth, либо поднять `[data-theme]` на `<html>` (но это сломало бы locked-theme поддеревья мокапов — поэтому выбран таргетинг Teleport).
