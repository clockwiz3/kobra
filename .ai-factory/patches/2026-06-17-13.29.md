# `composer run dev` падает на Windows: laravel/pail требует ext-pcntl

**Date:** 2026-06-17 13:29
**Files:** composer.json
**Severity:** medium

## Problem

`composer run dev` на Windows-машине разработчика падал целиком:

```
[logs] RuntimeException: The [pcntl] extension is required to run Pail.
[logs] php artisan pail --timeout=0 exited with code 1
--> Sending SIGTERM to other processes..
[queue] ... exited with code 1
[server] ... exited with code 1
[vite] npm run dev exited with code 1
```

То есть фронт-сборка (Vite) тоже умирала, хотя сама по себе работает.

## Root Cause

`scripts.dev` в composer.json — немодифицированный дефолтный шаблон нового
Laravel-проекта: `npx concurrently ... "php artisan serve" "php artisan
queue:listen ..." "php artisan pail --timeout=0" "npm run dev" --kill-others`.

- `php artisan pail` (laravel/pail) тейлит логи через долгоживущий процесс с
  обработкой сигналов и требует расширений **ext-pcntl/ext-posix**, которых
  в Windows-сборке PHP нет → процесс `logs` мгновенно падает.
- Флаг `concurrently --kill-others` после падения ЛЮБОГО процесса глушит
  остальные → вместе с pail умирают `server`, `queue` и `vite`.

Дополнительно скрипт не согласован с реальной моделью хостинга проекта:
PHP отдаётся через **Laravel Herd** на `http://cuploid.test` (см. `.env`
`APP_URL`), поэтому `php artisan serve` (поднял бы лишний `127.0.0.1:8000`)
не нужен, а `queue:listen` бессмысленен при `QUEUE_CONNECTION=sync`
(задачи выполняются синхронно инлайн).

## Solution

`scripts.dev` сведён к единственному реально нужному в этом сетапе процессу:

```json
"dev": [
    "Composer\\Config::disableProcessTimeout",
    "npm run dev"
]
```

- Убран `pail` — hard-краш без pcntl на Windows; логи читать из
  `storage/logs/laravel.log` или запускать `php artisan pail` вручную (на Linux).
- Убран `php artisan serve` — PHP уже отдаёт Herd на `cuploid.test`.
- Убран `queue:listen` — при `sync`-очереди воркер ничего не обрабатывает
  (вернуть, когда dev-очередь переедет на database/redis).
- Раз остался один процесс — `concurrently`/`--kill-others` больше не нужны
  (именно `--kill-others` превращал падение pail в полный обвал).
- `disableProcessTimeout` оставлен, чтобы Composer не убил долгоживущий Vite.

Проверка: `npm run dev` → `VITE v8 ready in 289 ms`, plugin видит
`APP_URL: http://cuploid.test`, падений нет.

## Prevention

- На Windows-деве избегать `pcntl`/`posix`-зависимого тулинга в составе
  оркестрируемых dev-команд: **pail**, `queue:work`/`queue:listen` с сигналами,
  Horizon — это Linux-/прод-инструменты (уже отмечено в `DESCRIPTION.md`).
- `concurrently --kill-others` оправдан только когда ВСЕ процессы обязаны жить;
  если один может легитимно отсутствовать на платформе — не валить им остальные.
- Дефолтный `composer dev` из шаблона Laravel надо приводить к фактической
  модели хостинга проекта (Herd `*.test` ⇒ `php artisan serve` не нужен;
  `QUEUE_CONNECTION=sync` ⇒ воркер не нужен).
- Для фронт-разработки на этом проекте достаточно `npm run dev` / `yarn dev`,
  открывать `http://cuploid.test` (HMR инжектит laravel-vite-plugin).
