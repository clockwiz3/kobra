# Мигающие скроллбары в принимающей колонке при drag карточки между колонками

**Date:** 2026-06-17 13:53
**Files:** resources/js/components/kanban/KanbanColumn.vue, resources/js/pages/Board.vue, resources/js/stores/board.ts, resources/js/components/kanban/__tests__/KanbanColumn.test.ts
**Severity:** low

## Problem

При перетаскивании карточки из одной колонки в другую в принимающей
колонке на ~160мс вспыхивали и горизонтальный, и вертикальный скроллбары
(`.kanban-col__cards` с классом `.ds-scroll`, который стилизует обе оси).
Визуальный «дёрг» при каждом переносе.

## Root Cause

Две сцепленные причины:

1. **CSS-гочча overflow.** `.kanban-col__cards` объявлял только
   `overflow-y: auto`, а `overflow-x` оставался дефолтным `visible`. По
   спеке (CSS Overflow 3): если одна ось не `visible`, а другая `visible` —
   `visible` форсится в `auto`. То есть контейнер молча становился
   скроллируемым **и по горизонтали**. Та же ловушка была на `.board-scroll`
   (`overflow-x: auto` → `overflow-y` форсился в `auto`).

2. **FLIP-анимация vuedraggable/Sortable.** При `:animation="160"` Sortable
   делает FLIP: после вставки карточки в новый DOM-узел он `transform:
   translate(...)`-ит её из старой позиции (старая колонка, другой x/y) в
   новую и анимирует трансформ к нулю. На время анимации карточка визуально
   находится за content-box принимающей колонки по обеим осям → overflow →
   оба (теперь активных) скроллбара вспыхивают.

Источник `@start/@end` приходит в **исходную** колонку, а мигает
**принимающая** (другой инстанс компонента), поэтому пер-компонентный флаг
не помог бы — нужен общий стейт.

## Solution

- `.kanban-col__cards`: задан **явный** `overflow-x: hidden` (вертикальный
  стек карточек по горизонтали не скроллится никогда) — убирает горизонтальный
  скролл насовсем.
- Общий реактивный флаг `dragging` в Pinia-сторе `board`. `@start` поднимает,
  `@end` опускает (на card-draggable в KanbanColumn и на column-draggable в
  Board). Класс `is-dragging` висит на `.board-main`.
- Неscoped CSS-правило `.is-dragging .kanban-col__cards { overflow: hidden }`
  клиппит overflow всех карточных списков на время жеста → FLIP-трансформ не
  порождает ни вертикального, ни горизонтального скролла.
- `.board-scroll`: добавлен явный `overflow-y: hidden` (лента доски скроллится
  только по горизонтали; колонки скроллятся внутри себя) — закрывает ту же
  гоччу на уровне доски.
- Логирование `[FIX] drag-start/drag-end` через существующий `useLogger`.

## Prevention

- **Никогда не задавать overflow по одной оси, ожидая `visible` на другой.**
  Если нужен скролл только по одной оси — явно писать обе: `overflow: hidden auto`
  / `overflow: auto hidden`. Иначе браузер форсит вторую ось в `auto`.
- При drag-and-drop с FLIP-анимацией (Sortable/vuedraggable) у скроллируемых
  контейнеров-приёмников клиппить overflow на время жеста — трансформируемый
  элемент временно выходит за их границы.
- Состояние, затрагивающее **другой** компонент-приёмник (а не только
  источник события), держать в общем сторе, а не в локальном `ref`.
- Code review: для любого `overflow-x`/`overflow-y` в одиночку — проверять,
  не нужна ли явная вторая ось.
