# Мигание мок-карточек на первичной загрузке доски (FOUC)

**Date:** 2026-06-17 14:21
**Files:** resources/js/stores/board.ts, resources/js/pages/Board.vue, resources/js/stores/__tests__/board.loading.test.ts
**Severity:** low

## Problem

При заходе на доску на долю секунды мелькал кадр с базовыми мок-карточками
(«Забронировать столик», «Купить цветы» и т.п.), которых у пары реально нет —
flash of unwanted content. После завершения маунта карточки исчезали/менялись
на настоящие.

## Root Cause

Стор `board` инициализирует `columns` сразу мок-данными:

```ts
const columns = ref<Column[]>(mockColumns())
```

Это сделано осознанно как graceful-фолбэк (commit ac34516) на случай
неавторизованного/безпарного состояния. Но реальная загрузка идёт так:

1. Компонент маунтится и **сразу** рендерит `store.columns` → на экране мок.
2. `onMounted(() => store.fetchBoard())` асинхронно ходит в API и только после
   ответа заменяет `columns` на настоящие.

В зазоре между первым рендером и ответом `fetchBoard` виден мок. Доска
закрыта `requiresAuth` (router `beforeEach` редиректит гостя на логин), поэтому
для реального зрителя мок — это всегда лишь «недозагрузка», никогда не конечное
состояние happy-path. То есть мелькание — чисто проблема loading-state, а не
данных.

## Solution

Введён флаг первичной загрузки `loading` (init `true`) в сторе:

- `fetchBoard` оборачивает тело в `try { ... } finally { loading.value = false }` —
  флаг гаснет один раз после первого ответа (успех или null-фолбэк).
- Флаг НЕ поднимается обратно в `true` при повторных вызовах `fetchBoard` →
  возврат на доску не вызывает повторного мелькания скелетона (данные уже есть).
- Мок-инициализация `columns` оставлена как есть (её ждут стор-тесты и она —
  легитимный фолбэк при сбое API), просто теперь скрыта за `loading`.

`Board.vue`: пока `store.loading` — рендерится скелетон (`v-if`), сама доска
`<draggable>` под `v-else`. Скелетон — колонки-плейсхолдеры с shimmer на
дизайн-токенах (`--surface/--surface-2/--border/--r-*`), поэтому подхватывает
все темы (включая pixel с нулевыми радиусами); shimmer отключается при
`prefers-reduced-motion`. На `<main>` повешен `aria-busy`, скелетон —
`aria-hidden`.

## Prevention

- Стор/композабл, инициализированный «дефолтными» данными ради фолбэка, обязан
  иметь явный `loading`/`ready` флаг — UI не должен показывать сид-данные как
  настоящие до первого ответа загрузчика.
- Loading-флаг для первичной загрузки сбрасывать «один раз навсегда», а не
  поднимать на каждый refetch — иначе скелетон мигает при каждом возврате на
  экран (стор в Pinia — синглтон, переживает навигацию).
- Скелетоны строить на дизайн-токенах, а не на хардкоде цветов/радиусов —
  иначе ломается мультитемность (тут 3 темы + pixel с r=0).
- Уважать `prefers-reduced-motion` для shimmer/анимаций (в проекте уже есть
  `prefersReducedMotion()` и паттерн `:animation="reduced ? 0 : ..."`).
