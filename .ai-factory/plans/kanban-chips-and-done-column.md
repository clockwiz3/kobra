## Контекст и проблема

Два связанных изменения канбана:

1. **Неконсистентные чипы (во всех темах).** На лице карточки (`KanbanCard.vue`) пилюли отрисованы сырыми классами `.chip`/`.badge` с **inline-переопределениями** размеров (`padding: 3px 9px` / `2px 8px` / `2px 7px`, `font-size: 11px`) и СМЕШИВАНИЕМ двух разных примитивов (`.chip` для исполнителя/меток и `.badge.warn` для дедлайна). Из-за этого три пилюли в одной карточке отличаются высотой, контуром и шрифтом; в теме `pixel` расхождение усиливается (`border-width`, `font-size`). При этом в проекте есть канонические компоненты `BaseChip`/`BaseBadge`, которые карточка обходит.
   **Цель:** все пилюли на лице карточки — единая геометрия (высота, контур, радиус, шрифт, паддинг) во всех 3 темах + 5 гаммах; отличаются ТОЛЬКО содержимым и цветом/фоном.

2. **Завершение задачи галочкой → через колонку.** Сейчас `done` — ручной булев флаг, переключаемый чекбоксом `.check` → `PATCH /cards/{id}/toggle-done` → геймификация `task_completed`. На дефолтной доске уже есть колонка `«Готово»`, но она обычная (никак не связана с `done`).
   **Цель:** убрать чекбокс; ввести неудаляемую **терминальную колонку** (репёрпоз существующей `«Готово»`). Перенос карточки в неё закрывает задачу (done=true), вынос обратно — возвращает в работу (done=false, upside-only, без отрицательной геймификации). Колонка выполняет роль галочки.

## Ключевые проектные решения

- **Терминальная колонка = существующая `«Готово»`** (репёрпоз, не вторая «готовая» колонка). Признак — новое поле `board_columns.is_terminal`. Ровно одна терминальная на доску (партиал-уникальный индекс Postgres).
- **`done` денормализован, но выводится из колонки.** Флаг `cards.done`/`completed_at` сохраняем (его потребляют `CardData`, фронт, стиль `.task.done`), но устанавливает его теперь `CardService::move` при пересечении границы терминальной колонки — не ручной toggle.
- **Идемпотентность/анти-фарм сохранены.** Геймификация `task_completed` остаётся с ключом `card_done_<id>` (повторный вход в терминал не начисляет заново). Возврат в работу — без отрицательных начислений (upside-only, см. ARCHITECTURE принцип 4).
- **Ограничения терминальной колонки:** запрещено только **удаление** (по требованию). Переименование и reorder остаются. Прямое создание карточки в терминал отключаем в UI (страховка на бэке выставит done на create в терминал).
- **Единый чип:** расширяем `BaseChip` пропом `tone` (`neutral`/`accent`/`warn`); геометрию задаёт один источник — класс `.chip` в `themes.css`. Дедлайн переезжает с `.badge.warn` на `.chip` с tone=warn. Карточка переходит на `BaseChip` вместо сырых span с inline-стилями.
- **Tenancy:** `board_columns`/`cards` — couple-owned (`CoupleScoped`). Бэкфилл в миграции по всем парам делается raw-DB с явным `couple_id` — документированное исключение для слоя миграций (app-код так не делает, см. ARCHITECTURE anti-patterns).

## Риски и заметки
- **Бэкфилл миграции** трогает couple-owned `board_columns` по всем парам: только в слое миграции, с явным `couple_id` от `board`. На текущем закрытом запуске данных мало, но логика должна быть корректной для N пар.
- **Партиал-уникальный индекс** — Postgres-специфика (`WHERE is_terminal = true`); проект на PostgreSQL (см. DESCRIPTION), это допустимо.
- **Согласование сигнатур** между задачами 4 и 5 (как `move` получает актора/целевую колонку) — зафиксировать при реализации задачи 4, затем подогнать контроллер.
- **`.task.done`** остаётся как визуальная подсветка закрытых карточек (теперь — тех, что лежат в терминальной колонке), завязан на `card.done`.
- **Прочие потребители `.chip`/`.badge`** (ui-library, свотчи `.swatch .chip`) не должны регрессировать — менять геометрию базового `.chip` аккуратно, проверить страницу ui-library.
